# Review Comment Guide

## Estructura recomendada

1. Clasificación.
2. Observación concreta.
3. Riesgo o impacto.
4. Acción esperada.
5. Referencia al estándar cuando aplique.

## Ejemplo

`REQUIRED: Validate the file type before storing the upload. Without this control, executable content could be persisted. Add an allowlist and a negative test.`

## Regla

El comentario debe poder entenderse sin una conversación privada adicional.
