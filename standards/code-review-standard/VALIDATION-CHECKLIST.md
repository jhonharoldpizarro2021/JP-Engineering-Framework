# Code Review Checklist

## Objetivo

- [ ] Comprendo el problema y el alcance.
- [ ] El cambio resuelve el objetivo.
- [ ] No contiene cambios ajenos.

## Funcionalidad

- [ ] Comportamiento correcto.
- [ ] Casos límite considerados.
- [ ] Manejo de errores adecuado.
- [ ] Compatibilidad preservada o documentada.

## Seguridad

- [ ] Sin secretos.
- [ ] Entradas validadas.
- [ ] Autorización correcta.
- [ ] Datos protegidos.
- [ ] Dependencias seguras.

## Diseño

- [ ] Responsabilidades claras.
- [ ] Complejidad justificada.
- [ ] Sin duplicación innecesaria.
- [ ] Nombres comprensibles.
- [ ] Arquitectura y estándares respetados.

## Pruebas y documentación

- [ ] Pruebas suficientes.
- [ ] Casos negativos incluidos cuando aplican.
- [ ] Documentación actualizada.
- [ ] Evidencia reproducible.

## Operación

- [ ] Logs y errores considerados.
- [ ] Migraciones seguras.
- [ ] Rollback documentado.
- [ ] Impacto productivo evaluado.
- [ ] Docker y CI/CD siguen funcionando.

## Decisión

- [ ] Approve.
- [ ] Comment.
- [ ] Request changes.

## Cierre

- [ ] Bloqueos verificados.
- [ ] Conversaciones relevantes resueltas.
- [ ] Nueva revisión realizada después de cambios materiales.
- [ ] Code Owner aprobó cuando aplica.
