# Validation Checklist

## Preparación

- [ ] Rama de origen válida.
- [ ] Rama base correcta.
- [ ] Rama actualizada.
- [ ] Sin commits WIP, fixup o squash.
- [ ] Sin conflictos.

## Título y descripción

- [ ] Título conforme al Commit Convention Standard.
- [ ] Resumen claro.
- [ ] Objetivo explicado.
- [ ] Ticket real vinculado cuando existe.
- [ ] Tipo de cambio indicado.
- [ ] Riesgos y efectos secundarios documentados.

## Calidad

- [ ] El Pull Request tiene un único propósito.
- [ ] No contiene cambios ajenos.
- [ ] Pruebas aplicables ejecutadas.
- [ ] Documentación actualizada.
- [ ] Evidencia suficiente.
- [ ] No contiene secretos ni datos sensibles.

## Integración

- [ ] CI en verde.
- [ ] Aprobaciones requeridas.
- [ ] Code Owner aprobado cuando aplica.
- [ ] Conversaciones bloqueantes resueltas.
- [ ] Sin solicitudes de cambio pendientes.
- [ ] Estrategia de merge correcta.
- [ ] Rama lista para eliminarse después de integrar.

## Riesgo

- [ ] Migraciones documentadas.
- [ ] Rollback definido.
- [ ] Seguridad revisada.
- [ ] Breaking changes identificados.
- [ ] Revisión adicional aplicada cuando corresponde.

## Resultado

- [ ] Aprobado.
- [ ] Aprobado con observaciones.
- [ ] Rechazado.
