# Naming Convention

Los ADR deberán nombrarse utilizando el formato:

ADR-001-GitFlow.md

ADR-002-Semantic-Versioning.md

ADR-003-Docker-First.md

---

# Buenas Prácticas

- Una decisión por ADR.
- Utilizar títulos claros.
- Registrar el contexto completo.
- Justificar la decisión.
- Documentar consecuencias.
- Mantener el historial.
- No modificar ADR aceptadas; crear una nueva que las sustituya.

---

# Excepciones

Toda excepción deberá:

- justificarse técnicamente;
- ser aprobada por el propietario del Framework;
- quedar registrada mediante una nueva ADR.

---

# Decisión Oficial

El JP Engineering Framework adopta Architecture Decision Records (ADR) como mecanismo oficial para documentar decisiones arquitectónicas y de gobernanza.

Toda decisión relevante deberá quedar registrada mediante una ADR siguiendo esta plantilla.

---

# Fuente de Verdad

Este documento constituye la plantilla oficial para la creación de Architecture Decision Records dentro del JP Engineering Framework.
