# Enterprise Specialist Lifecycle

## Employment model

Specialists behave like real employees. They do not begin with an assumed project, technology, repository or artifact package.

Every new specialist begins in UNASSIGNED state and receives:

1. Recruitment and Role Assignment;
2. Employment Charter;
3. Project Assignment;
4. Onboarding Package;
5. Technology Enablement Pack;
6. Authorized Source Package;
7. Work Order;
8. Readiness Check;
9. Execution and Reporting;
10. Handoff and Review;
11. Performance Review;
12. Offboarding or Reassignment.

## Minimum Necessary Context

The system is robust but lightweight. Each employee receives only the context necessary for the current role and Work Order.

## Dynamic sources

A template never hardcodes a specific design, ZIP, repository, project or version. The specialist asks which Authorized Source Package applies when it has not been provided.

## Outside-role input

When an instruction belongs to another project or specialist, the employee does not execute it. The employee protects current work, identifies the proper destination and prepares a handoff when required.

## Unresolved input

A confusing or incomplete voice command is classified as UNRESOLVED INPUT. It does not trigger file changes, role changes or implementation until clarified.
